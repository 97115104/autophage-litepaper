About this page

This page provides a guide to the Autophage Protocol's smart contracts. Each contract implements specific functionality from the litepaper, working together to create the metabolic economic system. The contracts are designed for gas efficiency, security, and upgradability. They implement the POTP (Proof of Temporal Persistence) token system with multi-species health incentive tokens. These contracts are demonstrative and should be considered experimental, not production-ready.

Repository: autophage-smart-contracts
Interactive Demo: https://97115104.github.io/autophage-litepaper/smart-contracts

1Introduction

The Autophage Protocol consists of four primary smart contracts that work together to implement the metabolic economic system described in the litepaper. These contracts handle token management with exponential decay, health activity verification through zero-knowledge proofs, community treasury operations, and empirical governance.

Key Design Principles: The contracts implement lazy evaluation for gas efficiency, modular architecture for upgradability, and privacy-first design with zero-knowledge proofs. All protocol changes require empirical validation, and biological scaling laws are embedded directly in the code.

POTP Meta-Token System

The protocol introduces POTP (Proof of Temporal Persistence) as the meta-token for cross-species settlement, governance, and protocol accounting. Users interact indirectly with POTP through species token conversions. This meta-token architecture enables cross-species liquidity management, unified governance across all token types, protocol-level accounting and settlements, and future cross-chain bridging capabilities.

2Contract Architecture

Contract interaction flow: Apps submit proofs to VerificationEngine, which mints tokens via AutophageToken. Decay flows to ReservoirContract, which handles healthcare settlements. GovernanceContract manages protocol changes.

AutophageToken.sol

The core token contract implements the multi-species token system with lazy decay evaluation. This is the foundation of the metabolic economy, where value decays exponentially without continuous renewal.

Token Species

Species Symbol ID Daily Decay Half-Life Use Case
Rhythm RHY 0 5% 13.51 days Exercise, medication adherence
Healing HLN 1 0.75% 92.42 days Therapy, recovery activities
Foundation FDN 2 0.1% 693.15 days Preventive care, long-term health
Catalyst CTL 3 2-10% Variable Marketplace balance

Key Functions

balanceOf(address user, uint8 species) → uint256

Returns current balance after applying lazy decay calculation. Gas efficient as decay is only calculated when needed.

transfer(address to, uint8 species, uint256 amount) → bool

Transfers tokens between addresses, applying decay to both sender and recipient balances.

lockInVault(uint8 species, uint256 amount, uint256 lockDays)

Locks tokens in wellness vault for reduced decay rates (30-365 days).

mint(address to, uint8 species, uint256 amount)

Mints new tokens. Restricted to MINTER_ROLE (VerificationEngine).

collectDecay(address[] users, uint8[] species) → uint256

Collects decayed value from user balances. Restricted to RESERVOIR_ROLE.

getAllBalances(address user) → uint256[4]

Returns all four token species balances for a user in a single call.

Decay Calculation

The decay formula implements exponential decay:

$$V(t) = V_0 \times (1 - \delta)^{days}$$

Where $\delta$ is the daily decay rate and $days$ is the number of days since last update.

ReservoirContract.sol

The Reservoir serves as the metabolic center of the protocol, implementing the dual-chamber architecture that separates decaying tokens from USDC reserves for healthcare settlements.

Dual-Chamber Architecture

Token Chamber: Collects decayed tokens for redistribution as activity rewards
USDC Chamber: Maintains liquidity for healthcare claim settlements

Key Functions

collectDecayedTokens(address[] users, uint8[] species) → uint256

Sweeps decayed value from user balances into the Reservoir for redistribution.

submitHealthcareClaim(uint256 amount, uint8 urgencyScore, string claimType, bytes32 verificationHash) → uint256

Submits healthcare claim with priority scoring (urgency 1-10). Returns claim ID for tracking.

processHealthcareClaims(uint256 maxClaims)

Processes pending claims in priority order up to available USDC balance.

distributeReward(address recipient, uint8 species, uint256 amount)

Distributes tokens as activity rewards. Called by verification engine after activity validation.

depositUSDC(uint256 amount)

Deposits USDC for healthcare settlements. Marketplace fees and other revenue streams deposit here.

calculateMetabolicPrice() → uint256

Calculates metabolic price based on system activity implementing endogenous pricing.

getReservoirStats() → (uint256[4], uint256, uint256, uint256, bool)

Returns comprehensive reservoir statistics including token balances, USDC reserves, and solvency status.

Solvency Requirements

Triple-coverage ensures healthcare access remains guaranteed:

$$R_{USDC}(t) \geq \max\left(0.4 \sum_u D_u(t), 3 \times \bar{H}_{monthly}, 0.22 \times Y_{annual}\right)$$

Healthcare Priority Formula

VerificationEngine.sol

Processes zero-knowledge proofs of health activities and calculates multi-factor rewards. This contract bridges the gap between private health data and public token rewards.

Key Functions

verifyAndMint(HealthProof calldata healthProof) → uint256

Verifies zero-knowledge proof and mints reward tokens. Restricted to registered apps.

registerApp(uint256 stakeAmount)

Registers verification app with required USDC stake (minimum 10,000).

evolveGeneticTrait(bytes32 profileId, string traitName)

Evolves a genetic trait by burning Foundation tokens. Cost increases exponentially.

batchVerifyAndMint(HealthProof[] calldata proofs) → uint256

Processes multiple health proofs in a single transaction for gas efficiency.

slashApp(address app, string reason)

Slashes a misbehaving app's stake with progressive penalties.

updateBaseReward(ActivityType activityType, uint256 newReward)

Updates base reward for an activity type. Restricted to ORACLE_ROLE.

$$M_{total} = M_{streak} \times M_{group} \times M_{time} \times M_{genetic} \times M_{synergy} \times M_{quality}$$

Subject to constraint: $0.3 \leq M_{total} \leq 20$

Cost(n) = 1000 × 2.5^(n-1) Foundation tokens

GovernanceContract.sol

Implements empirical governance where all protocol changes must demonstrate measurable health improvements through on-chain experiments.

Key Functions

createProposal(string title, string description, string hypothesis, ProposalType pType) → uint256

Creates new proposal with testable hypothesis. Requires 500 Catalyst token stake.

vote(uint256 proposalId, bool support)

Cast vote weighted by contribution score, not token balance.

startExperiment(uint256 proposalId, uint256 controlGroup, uint256 treatmentGroup)

Begins A/B test with specified user groups.

completeExperiment(uint256 experimentId, uint256 controlResult, uint256 treatmentResult, uint256 pValue)

Completes experiment with results. Validates statistical significance and improvement threshold.

updateContributionScore(address user, uint256 tokensContributed, uint256 successfulProposals)

Updates user's contribution score based on lifetime contributions.

trackFeatureUsage(bytes32 featureId)

Tracks feature usage for automatic sunset evaluation.

sunsetUnusedFeatures(bytes32[] featureIds)

Disables features with <1% usage for 180+ days.

Contribution-Based Voting

Voting weight calculated from lifetime contributions, not current holdings:

$$C_{score} = 0.5 \times \log_{10}(1 + R_{lifetime}) + 0.3 \times V_{reputation} + 0.2 \times A_{participation}$$

Experiment Requirements

Success Criteria: Experiments must demonstrate at least 5% improvement in the target metric with statistical significance (p-value < 0.05). Tests require a minimum 7-day duration and must include both control and treatment groups.

Proposal Process

  1. Stake 500 Catalyst tokens
  2. Community votes using contribution scores
  3. Run A/B test experiment
  4. Validate statistical significance
  5. Execute if successful, return stake + bonus

Automatic Feature Sunset

Features unused for 180 days with <1% utilization are automatically disabled.

  4. GovernanceContract: Deploy with token and catalyst addresses
